# Changelog
All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [0.0.1] - 2026-08-17

- First release.
- Preview: added a "🎨 Attributes" toolbar button — enabled once a field/constant is selected, same as "🗑 Delete" — that lets you set or clear `TEXT`, `COLOR`, `HIGHLIGHT`, `UNDERLINE`, and (numeric fields only) `EDTCDE` directly from the preview, one keyword per click via a QuickPick, instead of hand-editing the DDS source.
- Fixed: a `PAGNBR` constant couldn't be given an `EDTCDE` from the new "🎨 Attributes" button — `EDTCDE` was only offered for numeric fields, but DDS also allows it on `PAGNBR` (a page number is inherently numeric). The preview's placeholder now also reflects that edit code's width (e.g. `9,999` instead of the plain `9999`), same "worst-case 9s" convention as an edited numeric field. Also fixed `systemKeywordPlaceholder` (`prtf-edit.model.ts`) to recognize `PAGNBR` when it shares its line with another keyword (e.g. `PAGNBR EDTCDE(Y)`) instead of only a bare `PAGNBR` alone.
- Tree view: the "Definition" tree gained its first right-click context menu — "Edit Attributes..." on a field or constant node opens the same TEXT/COLOR/HIGHLIGHT/UNDERLINE/EDTCDE editor as the preview's "🎨 Attributes" button, without needing the preview open. First step towards bringing more of dspf-edit's tree-based editing (record create/delete/copy, indicators) to the tree here too.
- Fixed: a disabled preview toolbar button (e.g. "🗑 Delete"/"🎨 Attributes" before anything's selected) looked identical to an enabled one — the toolbar's own explicit button styling overrode the browser's default disabled dimming. Disabled buttons now render visibly muted, with a "not-allowed" cursor.
- Tree view: added record-level actions — an inline "+" icon on the "📂 Records" row (and "New Record..." on a record's own context menu, ordered before "Copy Record..." and "Delete Record") for creating a record, plus "Copy Record..." and "Delete Record" (with a confirmation naming how many fields/constants go with it). The "Records" row now stays in the tree (labeled with a count, e.g. "📂 Records (0)") even with zero records, instead of a plain "No records found" placeholder, so there's always something to click to create the first one.
- Tree view: added "Indicators..." to a field, constant, or attribute (keyword) node's context menu — add/remove indicators within an AND group (spilling onto continuation lines automatically past DDS's 3-per-line limit, up to 9 ANDed), add/remove a whole OR'd group, or clear everything, via the same one-action-per-click QuickPick convention as "Edit Attributes...". Required a small additive parser/model change (`PrtfField`/`PrtfConstant`/`PrtfAttribute.indicatorLineIndices`) to track which physical lines belong to an element's indicator conditioning — indicator continuation lines precede (not follow) the element they condition, unlike every other DDS continuation convention in this codebase. As a related fix, deleting a field/constant now also removes its own preceding indicator continuation lines instead of leaving them orphaned. Added an indicator example (`TITULO` in `samples/cabecera-report.prtf`) since no sample previously exercised indicators.
- Preview: added an "Indicators" toggle to the toolbar, full parity with dspf-edit's own "Simulate indicators on/off" — a checkbox enables simulation, then a row of per-number buttons (one for every indicator actually referenced in the record being previewed) lets you turn specific indicators on/off to see which fields/constants/keywords would actually print. Gates three things independently: whether an item renders at all, whether a conditionally-applied keyword (`COLOR`/`HIGHLIGHT`/`UNDERLINE`/`TEXT`/`EDTCDE`) on an otherwise-visible item takes effect, and — PRTF-specific, since DSPF has nothing analogous — whether a conditioned `SKIPB`/`SPACEB`/`SPACEA`/`SKIPA` contributes to the running flow position at all, so toggling one visibly shifts everything printed after it. `simulateRecordFlow` (parser) gained an optional `isAttributeActive` gate for this, defaulting to "always active" so every other caller (drag, add, edit-spacing, etc.) is unaffected. An overlaid/background record always renders at the resting state (every indicator off), never the live toggle, matching dspf-edit's overlay behavior. Added a conditioned `SPACEB(2)` (`IN30`) on `CANTIDAD` in `samples/detalle-flujo.prtf` to exercise the SKIP/SPACE case specifically.
- Tree view: added "Copy Field/Constant..." and "Delete Field/Constant" to a field/constant node's context menu — "Delete" reuses the preview's own `deleteElement` (including its indicator-continuation cleanup); "Copy" duplicates the entire block verbatim (`TEXT`/`COLOR`/`HIGHLIGHT`/`UNDERLINE`/`EDTCDE`, indicator conditioning, Line/Position) into a chosen record, except `SKIPB`/`SPACEB`/`SPACEA`/`SKIPA` — which describe the item's position *relative to whatever came before it in the flow*, not a property of the item itself — which you're asked about first. Positioning the copy afterward (either way) is a drag, same as a freshly copied record. Fields get a new-name prompt (validated, unique within the target record); constants don't need one.
- Fixed: the regex behind reading/removing `SKIPB`/`SPACEB`/`SPACEA`/`SKIPA` (`edit-spacing.ts`'s `keywordPattern`, and the parser's own flow-position simulation) required a word boundary before the keyword, which a digit immediately followed by a letter never satisfies — so a keyword written directly abutting a fixed-column zone with no space (e.g. `...+2SPACEB(2)`, the same shape this codebase's own samples already use for `DATE`, as in `...1DATE(*SYS *YY)`) was silently invisible to both. Found while testing the new "Copy Field/Constant..." spacing prompt. Now also matches when immediately preceded by a digit, while still rejecting a letter (so it can't match as a substring of a longer identifier).
- Fixed: the preview's "Overlay" selection was never actually cleared when switching which record is being previewed — only the picker's own option list excluded the active record, not the *stored* target — so a stale overlay from whatever record was active before silently kept applying to the new one. Now reset alongside the "Indicators" simulation state on every record switch.
- Changed how the tree/source/preview stay in sync, to match dspf-edit's own model: selecting a record/field/constant in the "Definition" tree now also points the preview at it directly (`RecordPreviewPanel.syncToLine`, called from the tree's own selection listener), instead of only moving the source cursor and relying on cursor movement to update the preview as a side effect. Moving the cursor around in the source editor on its own no longer changes the preview at all — the `onDidChangeTextEditorSelection` listener that used to drive it (`prtf-edit.listeners.ts`) is gone. Clicking a field/constant inside the preview itself still moves the source cursor and selects it in the tree, and now sets the preview's own selection directly too, rather than depending on the removed listener to loop back. The selected field/constant in the preview is now shown as a border around it (`outline: 2px solid`, matching dspf-edit) instead of a filled yellow background, so the O/6 placeholder text underneath stays legible.
